# Контракт формата CSV-выгрузки операций банка (Т-Банк)

> Источник-образец: [`samples/sample-operations.csv`](samples/sample-operations.csv)
> Оригинальное имя файла: [`samples/ORIGINAL_FILENAME.txt`](samples/ORIGINAL_FILENAME.txt) → `Operations Tue Sep 01 2026-Tue Sep 08 2026.csv`
> Период выгрузки: 01.09.2026 – 08.09.2026 (08.09.2026 22:41:24 … 01.09.2026 07:45:37, строки отсортированы от новых к старым).

Этот документ — **контракт для парсера** на следующих этапах. Все утверждения проверены на образце.

---

## 1. Общие параметры файла

| Параметр | Значение |
|---|---|
| Кодировка | **UTF-8, без BOM** (проверено `file`: `Unicode text, UTF-8 text, with CRLF line terminators`) |
| Переводы строк | **CRLF** (`\r\n`) в каждой строке, включая последнюю |
| Разделитель полей | **Точка с запятой** (`;`) |
| Ограничители полей | **Двойные кавычки** — **все** поля всегда заключены в `"` |
| Экранирование кавычек внутри поля | Удвоение `""` (RFC 4180). Пример: `ООО ""ВБ ТЕХ""` → при парсинге `ООО "ВБ ТЕХ"` |
| Экранирование разделителя | Не требуется: разделитель внутри полей не встречается, но поля в кавычках — стандартный RFC 4180-парсер его корректно обработает |
| Многострочные ячейки | В данном образце **не встречаются**, но RFC 4180-парсер обязан их поддерживать (поле в кавычках может содержать `\n`) |
| Пустая строка после последней записи | Нет — файл заканчивается `"` + `\r\n` |
| Заголовочная строка | Есть, 17 полей, имена на русском |

**Требование к парсеру:** использовать полноценный CSV-парсер (RFC 4180) с `delimiter=';'`, кавычками `"`, экранированием `""`; не разбивать по символу `;` наивным `split`.

## 2. Заголовки столбцов (17 шт., оригинальные названия)

| # | Заголовок | Семантика | Обязательность / особенности |
|---|---|---|---|
| 0 | `Имя счёта` | Название счёта/кошелька (например `общий`, `daily`, `Платинум`) | Ключ группировки по счетам |
| 1 | `Номер карты` | Маскированный номер карты `*1724` | **Может быть пустым** (7 из 117 строк: переводы между счетами, пополнения без карты) |
| 2 | `Дата операции` | Дата+время операции | Формат см. §3 |
| 3 | `Сумма операции` | Сумма в валюте операции | Формат см. §3; **знак**: `-` расход, без знака (или `+`-отсутствие) доход |
| 4 | `Валюта операции` | Код валюты ISO 4217 | В образце всегда `RUB` |
| 5 | `Сумма в валюте счёта` | Сумма в валюте счёта | В образце всегда равна «Сумме операции» |
| 6 | `Валюта счёта` | Код валюты счёта | В образце всегда `RUB` |
| 7 | `Статус` | Статус операции | В образце только `Ок`. Возможны иные значения (отмены/в обработке) — фильтровать по `Ок` |
| 8 | `Категория по-умолчанию` | Категория банка | Основной источник категорий; **не бывает пустым** в образце |
| 9 | `Ваша категория` | Пользовательская категория | Часто пустая; если задана — приоритетнее колонки 8 |
| 10 | `MCC` | Код мерчанта MCC | Может быть пустым (переводы/наличные); строка из 4 цифр либо `''` |
| 11 | `Описание` | Контрагент / назначение | Может содержать кавычки (`ООО "ВБ ТЕХ"`, `(Это Маша)`) |
| 12 | `Сообщение` | Комментарий/сообщение перевода | Обычно пустое |
| 13 | `Округление` | Флаг/значение округления | В образце всегда `0,00` |
| 14 | `Сумма операции с округлением` | Сумма с учётом округления | В образце всегда равна колонке 3 |
| 15 | `Бонусы (включая кэшбэк)` | Начисленные бонусы/кэшбэк | Десятичный формат как у сумм; в основном `0,00` (в образце 1 ненулевое: `250,00`) |
| 16 | `Учёт в аналитике` | Включать ли операцию в аналитику | Значения `Да` (99 шт.) / `Нет` (18 шт.). **Важно:** `Нет` — это в основном внутренние переводы «Между своими счетами» и пополнения — при агрегации их нужно исключать, иначе двойной учёт |

## 3. Форматы значений

### 3.1. Даты и время
- Формат строки: **`DD.MM.YYYY HH:mm:ss`**, пример: `08.09.2026 22:41:24`.
- **Часовой пояс: не указан в файле.** По умолчанию считать локальным московским временем (Europe/Moscow, UTC+3) — выгрузка из ЛК Т-Банка.
- Даты могут быть в будущем относительно реального «сегодня» (данные выгрузки — сентябрь 2026); не валидировать дату по «не раньше сегодня».
- Сортировка в файле: от свежих к старым. Парсер **не должен полагаться на порядок строк** — сортировать самостоятельно.

### 3.2. Суммы
- Формат: **запятая — десятичный разделитель**, **пробелов/разделителей тысяч нет**, кавычек внутри суммы нет.
- Примеры: `-83,00`; `-1049,94`; `229743,72`; `1,00`; `20000,00`.
- **Знак**: расход — с минусом (`-83,00`); доход/возврат/пополнение — без минуса (`229743,72`). Знак `+` в файле не встречается.
- Всегда 2 знака после запятой, но парсер не должен на это полагаться.
- Парсинг: `Number(value.replace(',', '.'))`; для точной арифметики с деньгами на следующих этапах — считать в копейках (`Math.round(parseFloat(x.replace(',', '.')) * 100)`) или использовать decimal-тип.
- «Сумма операции» (№3) и «Сумма в валюте счёта» (№5) в образце всегда совпадают (валюта `RUB`); для дашборда использовать колонку №3 (или №5 — при мультивалютных выгрузках №5 правильнее).

### 3.3. Валюта
- В образце все операции `RUB`. Код — ISO 4217 строка в колонках 4 и 6. Парсер должен принимать произвольный код, но дашборд пока предполагает единую валюту.

## 4. Идентификация операции (для дедупликации и связей)

Ключевые поля, идентифицирующие операцию:
- **дата-время** — колонка 2 (точность до секунды);
- **сумма** — колонка 3;
- **описание/контрагент** — колонка 11;
- **карта/счёт** — колонки 0–1;
- **статус** — колонка 7 (учитывать только `Ок`);
- **тип доход/расход** — выводится из знака колонки 3 (в файле нет отдельной колонки «тип операции»).

Стабильного ID операции (id/uuid) в файле **нет**. Время не уникально — дедупликация по кортежу `(Дата операции, Сумма операции, Описание, Номер карты/Имя счёта)`; при полном совпадении строк это вероятный дубликат выгрузки (см. §6).

## 5. Репрезентативные примеры строк (после CSV-парсинга, «сырые» значения)

1. **Обычный расход, карта, с MCC:**
   `общий | *1724 | 08.09.2026 22:41:24 | -83,00 | RUB | -83,00 | RUB | Ок | Местный транспорт | (пусто) | 4111 | Московский метрополитен | (пусто) | 0,00 | -83,00 | 0,00 | Да`
2. **Расход с пользовательской категорией (приоритет над дефолтной):**
   `общий | *1724 | 08.09.2026 15:39:08 | -576,00 | RUB | … | Ок | Фастфуд | Табак | 5814 | IP Unanyan Vg | … | Да`
3. **Перевод физлицу, без карты и без MCC:**
   `общий | *8576 | 08.09.2026 21:52:26 | -8000,00 | RUB | … | Ок | Переводы | Психолог | (пусто) | Екатерина Ш. | … | Да`
4. **Крупный перевод между своими счетами — дублируется по двум счетам, «Учёт в аналитике» = Нет:**
   `Платинум | *4782 | 08.09.2026 00:38:20 | 20000,00 | RUB | … | Ок | Переводы | (пусто) | (пусто) | Между своими счетами | … | Нет`
   `общий | *8576 | 08.09.2026 00:37:54 | 20000,00 | RUB | … | Нет` (зеркальная запись той же операции)
5. **Доход — зарплата, кавычки в описании (экранирование `""`):**
   `daily | *8586 | 04.09.2026 15:37:53 | 229743,72 | RUB | … | Ок | Зарплата | (пусто) | (пусто) | Пополнение. Начисление зарплаты. ООО "ВБ ТЕХ" | … | Да`
6. **Пополнение наличными через банкомат, без карты:**
   `общий | (пусто) | 03.09.2026 16:13:05 | 25000,00 | RUB | … | Ок | Пополнения | (пусто) | (пусто) | Внесение наличных через банкомат Т-Банка | … | Да`
7. **Возврат от мерчанта (плюс на карте, категория расходная):**
   `общий | *8576 | 06.09.2026 13:58:13 | 1,00 | RUB | … | Ок | Супермаркеты | (пусто) | 5411 | Перекрёсток доставка | … | Нет`
   (аналогичный возврат `Яндекс Такси` +1067,00 с «Учёт в аналитике» = Нет)
8. **Пополнение от другого лица:**
   `daily | (пусто) | 02.09.2026 16:30:43 | 2000,00 | RUB | … | Ок | Переводы | (пусто) | (пусто) | Светлана Ш. | … | Да`
9. **Вывод с брокерского/инвесткопилки (внутреннее движение, Нет):**
   `daily | *8586 | 02.09.2026 16:24:52 | 16800,00 | RUB | … | Ок | Переводы | … | Вывод с брокерского счета | … | Нет`
10. **Кэшбэк/бонус, единственная ненулевая строка бонусов:**
    строка «КуулКлевер» с «Бонусы (включая кэшбэк)» = `250,00`.

Краевые случаи, покрытые образцом: доходы и расходы; переводы «между своими» (двойные записи); пользовательские категории; пустые карта/MCC/категория-пользовательская; кавычки и скобки в описании; копеечные суммы (`1,00`); суммы с копейками и без округления.

## 6. Дубликаты, пропуски и особенности выборки

- **Явный дубликат:** одна строка встречается 2 раза полностью:
  `05.09.2026 01:10:13 | -83,00 | Московский метрополитен | -83,00 | *1724 | общий`.
  Вероятная причина — две реальные поездки метро с одинаковым тарифом за одну минуту (Т-Банк фиксирует каждую поездку) либо дубликат выгрузки. **Решение для парсера: полные дубликаты НЕ отбрасывать молча** — для метро это две поездки. Дедупликация нужна только при слиянии нескольких выгрузок с пересекающимися периодами (по кортежу всех полей).
- **Зеркальные записи** внутренних переводов «Между своими счетами»: одна реальная транзакция даёт 2 строки (списание на одном счёте, зачисление на другом, время на секунды различается). Для план/факта по доходам/расходам такие строки исключать по колонке «Учёт в аналитике» = `Нет` (18 строк) — но проверять, что доход-зарплата/пополнения с `Нет` не теряются (в образце `Нет` встречается и у возвратов).
- **Пропусков значений в ключевых полях нет** (дата, сумма, категория, статус заполнены во всех строках). Пустые значения допустимы только в: `Номер карты` (7 строк), `Ваша категория`, `MCC`, `Сообщение`.
- **Многострочных полей и пустых строк в конце файла нет**; каждая строка завершается `\r\n`.
- 117 строк данных; все строки имеют ровно 17 полей.
- Статус во всех строках `Ок` — правила фильтрации по статусу (`Ок` vs отменённые) на этом образце не проверяемы, но предусмотреть.

## 7. Рекомендации парсеру (сводка)

1. Чтение: UTF-8 (без BOM), `newline=''`; парсер RFC 4180 с `delimiter=';'`, `quotechar='"'`, `escapedoubled quotes`.
2. Первая строка — заголовки; сопоставлять колонки **по именам**, а не по индексам (порядок/состав колонок может отличаться в других выгрузках).
3. Даты: `DD.MM.YYYY HH:mm:ss`, таймзона Europe/Moscow → приводить к UTC/local при агрегации по неделям (недели — по ISO-неделям, старт понедельник).
4. Суммы: запятая как десятичный разделитель; знак — семантика расход/доход; считать в копейках.
5. Фильтр: `Статус === 'Ок'`; для дашборда — исключать `Учёт в аналитике === 'Нет'` (внутренние переводы), кроме специально обработанных случаев.
6. Категория: `Ваша категория`, если непустая, иначе `Категория по-умолчанию`.
7. Дедупликация полных строк — только при объединении нескольких выгрузок.
8. Не полагаться на сортировку строк и на уникальность секунды даты.
